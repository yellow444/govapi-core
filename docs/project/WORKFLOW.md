# Workflow

Keep an issue in the repository where the work will land. Core tracks shared design and country guides. Bell tracks free notification imports and the feed format. Track team features in the private repositories.

| Status | Meaning |
|---|---|
| **Backlog** | Planned work whose entry criteria are still open |
| **Ready** | The outcome, acceptance criteria, and dependencies are clear |
| **In progress** | The assignee has started |
| **Review** | The result and supporting evidence are ready for review |
| **Done** | The criteria are met, evidence is recorded, and the issue is closed |

Use milestones for phases and labels for work type and priority. Use the project board's Status field for shared progress. Take at most one implementation issue and one research issue per assignee at a time.

Public issues use official sources, reproducible scenarios, and synthetic data. Keep production credentials, real messages, and private implementation details in their authorized environments.
