# GovAPI Hub research

| Area | What to verify | How to use the result |
|---|---|---|
| **FIT-Connect** | Current SDK and schema, test destination, and the sender's right to read an event | Leading candidate for a technical demo. [Environments](https://docs.fitko.de/fit-connect/docs/getting-started/environments/) · [Event log](https://docs.fitko.de/fit-connect/docs/getting-started/event-log/get-events/) |
| **Smart Bridge** | Specific service and owner, participant role, TEST requirements, and official asynchronous response mechanism | Candidate for a partner pilot once access is confirmed. [Connection guide](https://new-sb.egov.kz/docs/ru/guides/kak-podklyuchitsya-k-servisu-na-smartbridge) |
| **Nothi** | Which systems can submit applications, query status, and receive a machine-readable response | Reference for an end-to-end flow between government offices. [Nothi API](https://nothi.gov.bd/API) |
| **Government mail for Bell** | Recipient role, legal effect of retrieval, attachments, IDs, and repeat reads | Compare DEHú, Mein Postkorb, Mina Meddelanden, App IO, and Digital Mailbox. Choose one documented test route. [Global directory](../countries/GLOBAL_INDEX.md) |
| **Source code availability** | License and scope of platform, client, SDK, or sample source | Compare Datovka, App IO, Digital Iceland, and Altinn. Record code licensing and platform access separately. [Global directory](../countries/GLOBAL_INDEX.md) |

Record the operation, role, owner, primary source, review date, version, access rules, and verifiable result in each research item. Keep case status, incoming messages, and delivery status separate. Record a decision to proceed, defer, or wait for a specific access requirement.
