# Japan · JP

Sources verified November 25, 2026.

## Portal and interfaces

The Digital Agency publishes Mynaportal specifications for electronic submission and receipt of notifications by separate interfaces, as well as procedures for service providers. To issue notifications to an external system, user consent and approval of the Digital Agency are required. Receiving applications and maintaining statuses on a separate API are described for municipal systems. [Mynaportal API](https://services.digital.go.jp/mynaportal-api/) · [Feed.](https://developers.digital.go.jp/documents/mynaportal-api/specification/eshinsei/) · [Notifications](https://developers.digital.go.jp/documents/mynaportal-api/specification/notificationinfo/) · [Obtaining applications and statuses for municipalities](https://developers.digital.go.jp/documents/mynaportal-api/specification/receiveinfo/)

## Core and Bell use cases

Core can describe the registration and one allowed feed path. Bell makes sense to evaluate separately on the message interface if you have the right user and partner. First, fix what operations are related to the application and what messages. The GovAPI Hub plug-in is not yet available.

## Free and open-source alternatives

Specifications and guidelines for integrators have been published, and the publicity of full-platform sources and free third-party delivery with the same coverage have not been confirmed.
